# 派活指令模板：睡前粘贴给执行的 Agent（Claude Code 或 Codex）的开工指令。
# 用法：复制 "----" 下面的内容，把【……】包住的占位换成真实内容后整段粘贴。
# 要改的地方：
#   1. 规范文件与任务书的路径。
#   2. 要点按任务书第 0 节挑最容易出错的几条重复一遍，其余让它读原文。
#   3. 模型与推理强度按“做错了谁能发现”选（见 01-方向 README 的模型选择一节）；涉及登录、权限、密钥的任务不降档。
#   4. 最后一行的轮数上限必须写，数字按任务大小定。
# 这份指令文本本身也存进仓库（例如 docs/dispatch/），以后能查到当晚交代了什么。
----
通读【规范文件路径，例如 AGENTS.md】与任务书 docs/【YYYY-MM-DD】-【功能名】-overnight-brief.md，然后按该任务书自主执行，目标是次日早上可以验收。

要点：
1. 任务书第 0 节是硬性规则，逐条遵守。特别注意：门禁必须用 `bash scripts/run-gate.sh verify` 运行，只认它最后一行的 `REAL_EXIT=`，不要接 | tail；多个 worktree 不要同时运行门禁；不用 git 回滚，不读写 /tmp。
2. 按第 3 节的轨道推进：【哪些轨道先并行开工，哪些轨道依赖谁】。每条轨道独立 worktree、独立分支、独立 Draft PR。
3. 第 2 节的设计决策已定，不要重新发明。【点名最容易被重新发明的那一条】。先读懂已有代码再动手。
4. 遇到产品决策（界面文案、设置项放在哪一层、是否改动已定接口、新增用户看得到的概念）停下来记进交付说明的“待拍板”一节，不要自己定，继续做下一个不依赖它的任务。
5. 界面改动必须产出截图，每个状态明暗各一张，存到证据目录 docs/evidence/【YYYY-MM-DD】-【功能名】/。这是次日验收的主要材料。
6. 不合并、不推送【集成分支】和【发版分支】、不开自动合并。
7. 收工条件见任务书第 6 节，全部满足才算完成；每完成一条轨道更新一次交付说明 docs/【YYYY-MM-DD】-【功能名】-delivery.md。
8. 你再派的子代理，必须把任务书第 0 节原样写进它的指令。

实现与复审用【模型】+【推理强度】；本任务涉及【登录 / 权限 / 密钥 / 数据迁移】，不降档；关键节点的安全复审用【旗舰模型】+【推理强度】。

or stop after 【N】 turns.
